# B5: `synaptics0078-setup` without Windows (design)

Recon step B5, 2026-10-17. Offline only: the sensor was not touched, there was no sudo, and nothing downloaded was executed (Python read it with `-I`). The detailed notes (every offset and timing) and the prototype scripts are local working files, not published.

Goal: on any 06cb:0078, `sudo synaptics0078-setup install` does four things:
1. downloads the public vendor cab;
2. takes the 10500-byte module out of it;
3. calibrates the reader on Linux;
4. writes `module.bin` and `program-<serial>.bin` to `/var/lib/fprint/synaptics0078`.

## Verdict

- **Every fixed byte can come from the download plus our code.**
  - `cmd02_template.bin` and both calibration-program skeletons were rebuilt **byte-exact** from each of four DLLs plus code: the 2019 cab, the 2020 cab, the 2017 Origin PC build and the Windows install.
  - The template sha256 and both skeleton pins all matched.
  - About 1.5 KB comes verbatim from the DLL, found by chunk header and checked against a sha256 pin. Our code generates the rest: about 120 B of literal protocol parameters, plus structure made by formula (lengths, counts, column entries, zero placeholders).
- **The rules behind three small groups of generated bytes are not traced in the DLL; they are reproduced and pinned.** These are a 6-byte patch in the timeslot table, the image-reconstruction parameter block and the six fixed line-update entries.
- **Extraction needs nothing new.**
  - bsdtar (libarchive, a dependency of pacman) unpacks both LZX cabs byte-identical to cabextract, also from stdin.
  - The Origin zip also needs a small stdlib OLE/MSI reader (prototype works).
- **Download:**
  - curl is a dependency of pacman.
  - Wayback holds byte-identical copies of both Microsoft cabs, but none of the Origin zip.
  - Private copies of all three sources are kept in `local/b5/` (local working files, not published), recorded in `SHA256SUMS` there.
- **Licence:** the package ships no Synaptics bytes today, and after B5 only hashes, URLs and the generated parameters. The project's own code is MIT (see `LICENSE`).

## Provenance of the fixed bytes

Class key:
- **a**: verbatim from the downloaded DLL, located by its 4-byte chunk header (type, length) and accepted only when sha256(header + data) equals the pin;
- **b**: protocol structure our code generates;
- **c**: per unit, zero in the template and filled from the calibration.

The DLL offsets are for the 2018 build in both cabs; the tool searches, it never trusts an offset.

| `02` program bytes | Chunk | Class | Source |
|---|---|---|---|
| 0–4 | header: opcode, bytes per line, req_lines | b | constants |
| 5–8, 1693–1696, 1773–1776 | 0x23, 0x17, 0x47 (empty) | b | type only |
| 9–1116 | 0x20, 0x32 ×3, 0x33 ×2: registers and register lists (1,084 data bytes) | a | 6 pins; 0x1dbfa4, 0x1e2f30, 0x1df390, 0x1df3bc, 0x1e0e40, 0x1dfa70 |
| 1117–1120 | 0x34 chunk header | b | type and length |

| 1657–1668 | 0x42 Data Encoder | a | pin; 0x1dfc90 |
| 1669–1692 | 0x2f, 0x29, 0x35 (u32 rows / offsets) | a or b | small values; also verbatim with headers at 0x1de018–0x1de028 |

| 10193–10256, 10335–10348 | 0x43 header and structure (count, 56 row indexes, three empty entries) | b | formula plus one format byte |

| 10349–18868 | 0x48 Baseline Frame | c | zero; the baseline frame (BF) |

Calibration programs #1 (1917 B) and #2 (10269 B): `calib_model.build_program` derives them from the template (header with req_lines 337, chunks 0x26/0x2e/0x47/0x48 dropped, 0x30 cut down or extended), so they take the template's provenance. Proof: the generated template gave both pinned skeleton hashes.

The three DLLs from the Windows install, the 2019 cab and the 2020 cab differ only in their Authenticode signature: their PE sections are identical, with build timestamp 2018-03-09. So every B2 address holds in the download. The 2017 Origin build is different code but carries the same tables.

**Files that held proprietary or third-party bytes at the time of the recon:**
- `proto/testdata/iusearch_cmd02.bin`, `toliknosov_cmd02.bin` and `toliknosov_cmd03.bin`. Each is a full third-party payload: the ~1.5 KB of DLL tables plus another unit's calibration. The iusearch repo has no licence.
- The untracked template is derived from `iusearch_cmd02.bin`.
- No module bytes appear in any tracked file. Elsewhere, the matches are only identifiers (function and chunk names).
- `proto/test_parsers.py` held RomInfo replies that their owners published in Validity90 issues; they include those units' serials. In the published tree those serial and unit-specific bytes are replaced with synthetic ones, and the three third-party payloads above are not tracked.

## Decisions

1. **Generate the template at install time from the DLL.**
   - The verbatim chunks are found by header and sha256 pin. The rest is built by code from named fields, and the final gate is the template sha256 pin.
   - Why: byte-exact on both known builds, so nothing proprietary is shipped beyond protocol parameters, and the pin makes any slip fail closed.
2. **Find the module by a pinned sha256 of its first 32 bytes, then its full sha256.** Scan at stride 16 first, then at stride 1.
   - Why: a plain sha256 window scan takes 6.6 s even at stride 16, while the prefilter takes 0.1 s, and under 2 s at stride 1.
   - It works on any container and any offset (0x19cca0 in 2018, 0x19e4c0 in 2017). A hash ships no bytes.
3. **Extract with bsdtar plus stdlib.**
   - bsdtar for cabs and zips, always `-xOf` to stdout (member names never become files). Stdlib for zips and for the OLE/MSI streams.
   - Why: libarchive is always present through pacman, and is tested byte-exact. cabextract and 7zip would be new dependencies for no gain.
4. **Parse as root only archives with a known sha256.**
   - Anything else (a re-signed cab, `--from-file`, a URL) is parsed in an unprivileged child: `setpriv --reuid=65534 --regid=65534 --clear-groups --no-new-privs` running the packaged extractor. The input goes in on stdin; the output comes back on stdout, size-capped. The root side then applies the pins.
   - Why: libarchive's CAB/LZX code has a CVE history, and this tool runs as root.
5. **Download with curl.**
   - argv: `/usr/bin/curl -q --proto =https --proto-redir =https --tlsv1.2 --fail --location --max-redirs 3 --connect-timeout 20 --max-time 300 --max-filesize CAP --retry 2 --retry-delay 2 --silent --show-error --remove-on-error --output FILE URL`.
   - CAP: 16 MB for a cab, 32 MB for the zip. `--max-time 600` for Wayback.
   - Try the sources in the order of the table. Stop at the first one that gives the pinned module **and** a template with the pinned hash.
   - Why: `-q` ignores root's curlrc; the cap and `--fail` were tested (exit 63, exit 22). The archive hash is a convenience; the module and template pins are the gates.
6. **`--from-file FILE`, repeatable.**
   - Accepts a cab, zip, setup exe, MSI, DLL, bare module or bare template, detected by magic bytes or by exact size.
   - Gated only by the module and template pins. Through sudo, the file must belong to the sudo user.
   - A bare module alone cannot be calibrated (calibration also needs a DLL, an archive or a template), and the tool says so.
7. **Cache what was fetched in `/var/lib/synaptics0078/vendor/`** (root, 0700).
   - It keeps the verbatim archive as `<sha256>-<name>` plus a manifest (URL, date, what it gave). The cache is tried before the network, so a reinstall works offline.
   - Why: FHS `/var/cache` must be regenerable, and here the source may disappear, so this is state. It also stays out of fprintd's own state dir and print store.
8. **Share the code as one package in the repo, `synaptics0078/`.**
   - `calibration.py`, `calib_model.py` and `parsers.py` move there, joined by `pins.py`, `vendor.py`, `template.py` and `session.py` (the USB transport, command guard and calibration sequence, taken out of `proto/calibrate.py`).
   - The proto modules become shims that alias the package module (`sys.modules[__name__] = …`), so every import and every monkeypatch keeps working.
   - The PKGBUILD adds this repo as a second `git+file` source pinned to a commit (phase C: the public URL). It installs the package into a private `/usr/lib/synaptics0078/`, and the setup script from the same checkout.
   - Why: makepkg rejects a directory as a local source (tested). A git source packages only committed code. A private dir survives Python minor upgrades, which site-packages does not without a rebuild.
9. **Run the calibration inside the setup with calibrate.py's own guard.**
   - The guard: closed command allow-list, skeleton pins, a single module upload, stop commands on every exit. Variant L only.
   - Order:
     1. Find the reader in sysfs before any download.
     2. Stop fprintd if it is active (one line). It restarts on demand.
     3. Claim the interface; on busy, retry once, then give a clear message.
     4. "Keep your fingers off the reader, then press Enter" (with `--yes`, a 3-second countdown).
     5. A check score above 200 gives a retry prompt, at most 3 times; the baseline sanity gate runs too.
   - The serial comes from RomInfo, as the driver derives it, and is cross-checked against the sysfs USB serial. They matched on this unit (compared without printing).
   - If no module is loaded, upload it. If an unexpected module is loaded, refuse and ask for a restart.
   - Why: the guard and sequence passed on hardware in B2.
10. **Check a program without template bytes.** Zero the per-unit regions of an installed program; for a valid program, its sha256 equals the template pin.
    - Why: `status` and `install` can then fully validate a program without the DLL at hand.
11. **Make `install` idempotent**, and make `recalibrate` explicit.
    - A valid module plus a valid program for this reader means "already set up", with no download and no calibration.
    - `recalibrate` keeps the previous program under `/var/lib/synaptics0078/backup/`. Prints enrolled before still match (B2b).
    - Package upgrades never touch the data. If the template pin ever changes, re-splice the per-unit regions of the installed program into the new template; no recalibration is needed.
12. **Phase C.**
    - In `omarchy-setup-security-fingerprint`, when sysfs shows 06cb:0078, install `libfprint-sigfm-0078` instead of `libfprint-git`, then run `sudo synaptics0078-setup install`, before enrolling.
    - The package's `.install` file only prints the command; it never runs it.
13. **Licensing housekeeping before phase C.**
    - Add a LICENSE (done: MIT for the project's own code).
    - Untrack the three third-party payloads in `proto/testdata/` (keep them in a gitignored place; their tests skip when they are absent) and replace their coverage with synthetic fixtures.

## Proposed command line

```
sudo synaptics0078-setup install                  # whatever is missing: vendor files, calibration, files; idempotent
sudo synaptics0078-setup install --from-file F    # offline or manual source (repeatable)
sudo synaptics0078-setup install --from DIR       # Windows-derived files (phase A), unchanged
sudo synaptics0078-setup recalibrate              # new calibration, previous program backed up
sudo synaptics0078-setup fetch [--from-file F]    # vendor files into the cache only; no reader needed
     synaptics0078-setup status                   # ready or not; with sudo it also looks inside /var/lib
common options: --dry-run, --yes
```

A good run:
```
Fingerprint reader 06cb:0078 found.
Getting the vendor files (Microsoft Update Catalog)... done, checked.
Keep your fingers OFF the reader, then press Enter.
Calibrating... done.
Ready. Enroll a finger with: fprintd-enroll   (log: /var/log/synaptics0078-setup.log)
```

Failure lines say what to do next. For example: "Could not download the vendor files from any source. Download one of them yourself (`synaptics0078-setup status` lists the URLs) and run: `sudo synaptics0078-setup install --from-file FILE`". Debug detail goes only to the log (root, 0600, serial redacted).

## Risks

| Risk | Handling |
|---|---|
| The public files disappear | 5 sources (2 on Wayback), the local cache, `fetch` ahead of time, `--from-file`, a private archive |
| Microsoft re-signs a cab | new cab hash means unprivileged parsing; the module and template pins still pass |
| A DLL build without one of the tables | the template pin fails and the next source is tried; both known builds work |
| The 3 untraced rules | byte-exact and pinned today; another sensor revision is refused anyway (ROM and type checks) |
| A root tool parsing untrusted archives | decision 4 |
| A finger on the reader during calibration | check score and baseline gates, then a retry prompt |
| fprintd or the lock screen holds the reader | stop, claim, retry once, clear message |
| The wrong module is resident (e.g. after Windows) | refuse and ask for a restart (long term: the driver checks the module id) |
| sudo drops `https_proxy` | document `sudo --preserve-env=https_proxy`, or use `--from-file` |
| The calibration programs' timeslot words may differ from Windows' (never seen on the wire) | ours passed on hardware in B2 |
| Licence: third-party payloads tracked | decision 13 |

## Implementation plan

No hardware is needed until acceptance item 1. Three stages.

### B5a: the shared package (no behaviour change)
- Files:
  - new: `synaptics0078/__init__.py`, `pins.py`, `template.py`, `vendor.py`, `cfb.py`, `session.py`, `tests/`;
  - moved: `proto/{calibration,calib_model,parsers}.py` → `synaptics0078/`, with alias shims left in `proto/`;
  - `proto/calibrate.py` uses `session.py`;
  - `tools/synaptics0078_data.py`: import path only.
- `template.py`:
  - `build_from_dll(dll: bytes) -> bytes` (raises when a pin is missing, checks the template pin);
  - a CLI `python3 -m synaptics0078.template --dll PATH --out proto/data/cmd02_template.bin`, so a fresh checkout can recreate the template file.
  - The constants and pins are ported from the recon prototype script (local working files, not published), naming each field. No table bytes in source.
- `vendor.py`:
  - detect the input type;
  - bsdtar list then `-xOf -` from stdin;
  - zip via `zipfile`;
  - OLE/MSI cab streams via `cfb.py`;
  - module scan (head-hash prefilter, stride 16 then 1);
  - size caps everywhere;
  - returns `(module, template, provenance)`.
- `pins.py`: the module, module-head, template and skeleton pins, the chunk pins, and the known archives (URL, size, sha256).
- Untrack `proto/testdata/*_cmd0[23].bin` into a gitignored dir. The tests that use them skip when they are absent.

### B5b: the setup tool
